# 四维 Jev 评分标准 — attractiveness-v4

这是 OII-397 已确认标准的正式评分口径。`career_ops/evaluation/score_graph.py`
通过三维公司 agent 与 Jev 评分入口执行本文锚点；报告、数据库与 Dashboard 保留四维原始结果。
历史评分不改写。初期推荐仅按四维分数：四维均有数值且各自 ≥4 才进入 focus，否则 deprioritize；明确硬性不符合仍 discard。confidence 与独立充分性继续展示，不设推荐门槛，不因低充分性阻断或自动复核。

标准依据为 [OII-397](https://linear.app/oii-workspace/issue/OII-397) 及用户后续确认。

## 共同口径

- 四个正式维度为 `direction`、`company`、`culture`、`compensation`，各自保留 1–5 小数分、Jev 原始评分 `confidence` 和独立证据充分性；不计算总分、均分或跨维度总排名。
- 以下整数档是小数评分的近似文字锚点。Jev 分布期望分只需大致遵循分档及吸引力趋势，不要求精确等于锚点或机械受其数值限制；单休对应的 1.x、大小周对应的 2.x 等邻近小数不因微小偏移判为不合格。保留原始期望分与 confidence，不取整、截断或确定性封顶，也不新增固定加减分或插值公式。分数描述吸引力，充分性描述现有材料是否足以支持该维度判断；不能把资料少写成低分，也不能把未知填成 3 分。这项近似容许不改变已确认的推荐分数门槛。
- 证据不足时仍保留有效模型响应中的原始分数并标注“证据不足／待核实”。缺失本身不奖励或惩罚岗位；已有相关事实仍可作为决策参考。高 `confidence` 不补足缺证；充分性也不是资料覆盖百分比。
- 公开调研服务于岗位初筛。优先查可公开取得的经营、产品、员工体验、福利和薪酬信息；不要求内部预算、未来编制、目标团队近期排班、经理内部操作或个人 offer 条款。`gaps` 只保留重要且有合理公开检索路径的问题，可以为空；这些内部问题不作为缺口清单或充分性扣分依据。已公开的具体信息仍可保留。
- 同公司集团制度、其他团队体验、历史资料及参考职级薪酬，即使尚未确认适用于本岗位，也可纳入评分与决策参考。保留来源、时间、地区、职级、团队及局限，不改写成已确认岗位条件。已知范围不同与范围未知分别说明；无关雇主、行业泛化金额和没有来源的猜测仍不可用。
- 低评分 `confidence` 只提示用户留意；不设独立推荐门槛、不自动调用 LLM 复核、不增加等待人工批准状态。用户反馈偏高或偏低后修改标准，再用真实保留岗位验证。
- 只使用所提供的可追溯证据。保留来源、日期、实体、地区、职级或团队范围、自述性质及冲突；搜索线索不等于已取得正文，未找到投诉不等于正面事实。
- 候选人的能力、年限、资格门槛和岗位真实性单列。候选人不会某项技术不降低 `direction`；雇佣、城市、人数等门槛不转换为吸引力扣分。
- API 报错或无效响应允许有限重试；仍失败则记录失败并保留证据，等待后续重试。不虚构分数，不切换到 LLM 生成替代分数。本项不设重试次数。

## 维护单位与岗位引用

`direction` 按岗位评价。`company`、`culture`、`compensation` 的公开研究及基准评价按公司维护，
由岗位引用适用的公司档案版本；不因同公司新增岗位而重复研究或重新生成同范围的公司评分。
正式入口为 `.venv/bin/python -B -m career_ops task start score ID scan:ID --re-evaluate`；
`career_ops/evaluation/company_pipeline.py` 维护公司档案，实验 CLI 复用同一实现。

正式流程先由公共 JD 范围规划节点声明公司实体和范围，再由一次 Codex CLI 任务共同完成缺失的 company/culture/compensation 调研与事实整理。使用已登录的 ChatGPT 账户、gpt-6-astra、medium reasoning 和实时搜索；一次任务覆盖全部待查范围，最长 15 分钟。正式入口没有自研搜索／逐篇摘要循环。
研究仅接收公开公司资料和公开 JD，不接收 CV、个人偏好、评分标准或旧分数。使用临时只读目录、忽略用户配置，禁止额外 agent、skill 和目录外文件访问；项目 API 密钥不传入子进程。
每条事实保留来源 URL、日期、性质、适用范围和局限，未知和冲突单列。程序检查结构、profile 身份和来源 URL；空事实不评分。各维度的非空事实分别交给 Jev，个人标准仅用于评分。
保留原始输出、提示词、工具事件、耗时、已报告用量和失败记录。工具日志／引用不是完整网页正文存档，不冒充已取得全文。超时终止整个 CLI 进程组，不自动回退；后续尝试启动新任务，已经完成的事实和分数仍可复用。
当前范围档案在有效期内、研究规则未变时复用；新增范围只查缺失范围，研究规则变更或过期重新调研，评分规则变更只重跑 Jev。历史证据和分数不改写。

公司档案须明确雇主实体或集团关系，名字规范化只辅助查找，不自动合并同名公司、子公司或招聘代理。
`company` 保留经营与技术证据的实体范围；`culture` 按地区和已知团队范围维护；`compensation`
按地区、岗位族、职级、币种及年薪口径维护。三维均保留原始小数分、confidence、独立充分性、
来源及缺口；公司基准不保证具体岗位条件或 offer。

岗位引用范围必须明确匹配。多地 JD 不擅自确定单城；Senior 或经验年限不推成具体 IC 等级；
未知职级不自动映射到具体档位，跨地区金额不冒充目标地区薪资。当前档案内可保留参考职级、其他团队或地区的相关原始事实用于有边界的判断；档案键匹配不要求每条参考事实都已证实适用于目标岗位。没有匹配档案时不能直接
借另一范围的已算分数。岗位明确报价单列为岗位薪资判断，并保留引用来源，不改写公司基准。

新公司、未覆盖的地区或职级、已过期的资料及实质新证据需要补查或更新公司档案。输入证据、
适用范围或标准变化后生成新版本，旧版本及当时岗位引用保留；相同输入复用已有结果。
正式档案有效期截止本周日，最长七天；该有效期同时进入正式输入指纹，跨周旧评分标为过期。
实验入口仍接收显式截止日期。档案与原始来源留在 data/company-profiles，正式公司评分和岗位引用由
SQLite 同事务保存。充分性阈值不由程序擅自设定。

## direction：工作内容与职业方向

评价实际主责、产品贡献和责任范围。首选 Agent / Applied AI 产品工程，其次为全栈、后端产品工程；AI Platform / LLMOps 属相邻方向。岗位名称或使用 AI 工具本身不能证明实际工作方向。

| 分数锚点 | 工作内容的文字标准 |
| --- | --- |
| 1 | 主要工作明确偏离软件／AI 工程方向，难以积累所追求的应用或产品工程经验。 |
| 2 | 与软件／AI 有关，但主要工作明显偏离应用与产品工程，需要较大职业方向妥协；例如以模型理论或训练研究为主，应用系统交付并非主要职责。 |
| 3 | 可接受的通用软件工程工作，能继续积累工程经验，但产品贡献和首选方向的联系有限。 |
| 4 | 有明确的全栈、后端或 AI 工程职责，并对具体产品产生工程贡献；尚未达到首选 Agent / Applied AI 产品系统主责及端到端责任的程度。 |
| 5 | JD 明确将首选 Agent / Applied AI 产品系统作为主要职责，并承担从设计到交付或运营的责任。 |

**独立充分性问题：**

> 现有岗位正文是否足以识别主要工作、具体交付对象和责任范围，从而判断它与候选人首选、次选及相邻工程方向的关系？判断依据是否来自实际职责，而非标题、关键词、公司声誉或候选人的技能缺口？

支持充分的材料能说明“主要做什么、交付什么、负责到哪一步”，也能支持明确偏离偏好的低分。只有标题、泛化宣传、零散关键词，或正文关键职责被截断时，说明这些缺口；不因模型能输出数字就认定充分。研究与应用职责并存时，依据主责和交付对象判断，不因出现“研究”或“Agent”单个词就落档。

## company：经营与持续技术投入

只评价经营稳定性、持续技术投入及工程发展条件。文化、工时、管理和员工待遇由 `culture` 评价。经营强劲不能抵消可靠的负面文化事实。

| 分数锚点 | 经营与技术条件的文字标准 |
| --- | --- |
| 1 | 存在严重经营持续性问题，或技术能力被实质性放弃、拆解，工程工作的长期基础受到严重威胁。 |
| 2 | 经营稳定性或技术支持存在明显问题，例如持续收缩、投入中断或工程资源严重不足，需要较大妥协。 |
| 3 | 业务可持续开展，存在实际技术团队或产品建设，但经营韧性、投入连续性或工程发展条件有明确且可接受的短板。 |
| 4 | 经营稳健，持续支持技术建设：业务能够持续经营，技术团队和投入有连续性，工程建设得到实际支持。稳定的中型公司也可达到，不要求大厂或高速增长。 |
| 5 | 在 4 分基础上具有更好的业务韧性和长期技术发展条件，能够持续支持有价值的技术建设。规模、名气、营收或资金量不能单独支撑高分。 |

**独立充分性问题：**

> 现有可追溯的经营和技术建设事实，能否为所声明公司或集团范围的初筛判断提供有边界的参考？集团财务、研发和产品事实可支持集团层面判断，不要求目标岗位的内部预算、未来编制或安全保证；公开风险事件按已知范围解释。

两方面都应有依据，但不强制公开财报、研发金额或上市公司材料。持续经营情况、技术团队连续性、持续产品建设和实际工程支持均可成为证据。投入计划与已完成投入分开；集团情况不直接证明本地岗位安全。单个招聘 JD、单一岗位项目、公司名气或人数不能替代经营与持续投入事实；不能把招聘代理或同名公司的材料当实际雇主证据。

业务收缩、规模性裁员、管理层调整和股价大幅波动是核查经营与技术连续性的调查信号，不按新闻条数机械扣分。核实事件是否已发生、影响哪项业务或技术团队、是否持续，以及有无相反证据；管理层变化或股价波动本身不等于经营衰退。未上市公司不因没有股价信息扣分，未搜到负面新闻也不证明经营稳健。

缺少任一方面时，保留模型原始分数并让充分性反映缺口。另一面的高分、文化材料或丰富财报不能自动补足缺失的一面。不新增经营／技术子分的平均、权重或取最小值公式。

## culture：工时、管理、协作与员工待遇

评价公司工作体验，包括工时、带薪年假、假期制度、弹性工时、管理、协作和员工待遇。优先研究公开员工体验和福利制度；来源提供几险几金、缴纳基数、比例或条件时保留，不逐项追问。区分法定最低要求、雇主额外制度、官方承诺与实际执行。同公司其他团队或地区的资料可提供参考，不直接证明该岗位或团队的具体排班。

| 分数锚点 | 工作体验的文字标准 |
| --- | --- |
| 1 | 单休或每周净工作时长至少 48 小时，通常对应接近 1 分的较低吸引力；或存在严重伤害员工的工作方式，例如普遍强迫无补偿超时工作、羞辱或报复性管理，工作节奏与基本尊重受到严重破坏。 |
| 2 | 大小周或每周净工作时长超过 40 小时但不足 48 小时，通常对应接近 2 分的较低吸引力；或虽为双休且不超过 40 小时，但存在明显且反复的管理、协作或待遇问题，需要较大妥协。严重问题仍可支持更低档判断。 |
| 3 | 双休且每周净工作时长不超过 40 小时，但工作节奏、自主权、管理、协作或待遇仍有明确且可接受的妥协。这里描述已知的妥协，不表示资料缺失。 |
| 4 | 正常双休且每周净工作时长不超过 40 小时，工作节奏可持续、管理尊重人、协作正常；偶发加班有合理补偿，管理不羞辱或强迫员工，团队能够正常沟通协作；不要求特殊福利。 |
| 5 | 在 4 分基础上，进一步体现更好的自主权、信任与工作安排，员工能更好地掌控工作方式和个人时间。 |

每周净工作时长 `H` 扣除可自由支配的午休和其他休息，计入实际工作、待命及常态加班；午休期间仍需工作或待命的时间不能扣除，也不按个人产出效率缩减工时。偶发加班单列其频率、时长与补偿，不冒充正常周安排，也不忽略其影响。

文化吸引力同时参考休息制度与净工时，并按较差工作安排对应的较低档判断：单休约 1 分、大小周约 2 分，正常双休才支持 3 分及以上的档位；`H ≤ 40` 才支持 3 分及以上的档位、`40 < H < 48` 约 2 分、`H ≥ 48` 约 1 分。这些是近似锚点，不是对原始期望分的确定性 cap；1.2 或 2.04 等邻近小数不因略越整数判为失败。双休且不超过 40 小时不自动保证高分；管理、协作、假期、弹性安排和员工待遇仍影响最终判断，也不能用额外福利抵消已知的明显不利作息。

| 已知工作安排 | 每周净工作时长 | 参考文化档位 |
| --- | --- | --- |
| 9:00–18:00，可自由支配午休 1 小时，每周五天／双休 | `(9 − 1) × 5 = 40` 小时 | 支持 3 分及以上档位，仍需判断其他文化事实。 |
| 9:00–19:00，可自由支配午休 1 小时，每周五天／双休 | `(10 − 1) × 5 = 45` 小时 | 接近 2 分档，允许邻近小数。 |
| 双休，每日净工作 10 小时 | `10 × 5 = 50` 小时 | 接近 1 分档，允许邻近小数。 |

未知工时不默认 40 小时，也不因缺失而罚为低分或自动否定其他文化参考。上述作息锚点用于有相应资料的情况；未取得精确工时仍可依据具体员工体验、管理和待遇事实形成初步判断，不要求补造排班。已知的单休等事实仍保留；公司层面工时不直接填成本岗位工时。

**独立充分性问题：**

> 现有员工体验或公开制度，能否为工作节奏、管理协作或待遇提供具体的初筛参考？已公开的休息制度、净工作时长、休假和福利均可采用；无需逐项齐备。官方承诺、其他团队或地区的体验可以提供参考，保留范围与局限，不要求确认目标团队执行；只有影响核心事实可信度或含义的缺口与冲突才妨碍参考判断。

官方制度能证明承诺，不能自动证明执行；法定最低要求不能自动证明雇主按要求落实，也不能当作额外福利。公开材料提供假期、弹性工时或社保／公积金细节时记录已知范围和条件；不要求内部审批规则、实际休假记录或逐项缴纳证明，未知不补成当地惯例。员工反馈保留实际范围，单条匿名反馈也可作为有限参考，独立、近期且一致的多条反馈更有判断价值；本标准不指定条数或有效期阈值。不同团队的体验差异分别呈现，不自动视为互相否定；核心事实的实质冲突影响充分性，不把相反描述平均成“文化一般”，不因官方身份自动忽略员工反馈。

`955.WLB`、`996.ICU` 作为研究线索，不作为保证或黑名单。没有投诉、知名外企身份和经营强劲不证明文化好。依据现有个人偏好，适用于中国大陆／香港的实质远程安排可作为工作安排的正面事实；现场办公不因此扣分，远程标签不能替代其他文化事实，也不新增固定加分值。

文化低分与是否具备某项资格是不同判断；不把文化问题加减到 `company`。薪资高也不提高 `culture` 分数。

## compensation：相对个人底线与目标的薪资

采用岗位报价、同公司薪酬样本和公开薪酬制度作为决策参考，优先同地区、相关岗位族和参考职级。尚未确认岗位定级不排除这些样本；明确实际样本范围，不将岗位标题强行映射为公司职级。基准评价的是预期吸引力，不等于本岗位 offer，也不证明个人收入门槛已经通过。

只按年薪比较，不因每日或每周工时调整个人底线或目标。下表中 `r = 可比年薪 / 所在地区个人年薪底线`；收入、底线及目标上限必须具有相同币种和地区规定的薪酬口径。比例区间、达到底线约 4 分及达到目标上限约 5 分都是大致锚点；保留邻近小数，不要求精确输出对应整数。

| 分数锚点 | 薪资相对个人偏好的文字标准 |
| --- | --- |
| 1 | `r < 0.70`，可比薪资不足个人底线的 70%。 |
| 2 | `0.70 ≤ r < 0.90`，达到底线的 70%，但不足 90%。 |
| 3 | `0.90 ≤ r < 1`，达到底线的 90%，但尚未达到底线。 |
| 4 | `r ≥ 1` 且可比薪资尚未达到适用目标上限，即达到个人底线、未达 5 分锚点。 |
| 5 | 可比薪资大于或等于适用的个人目标上限。按地区规定的薪酬口径比较，总包不能冒充保证底薪，浮动或一次性收入不能冒充可持续保证收入。 |

**个人年薪金额与比较口径：**

| 地区 | 基础年薪底线与目标上限 | 比较口径 |
| --- | --- | --- |
| 大陆一线城市 | 底线 CNY 350K；目标上限 CNY 400K | 税前年总包，区分底薪、保证奖金、浮动奖金、股权及一次性收入。 |
| 大陆新一线城市 | 底线 CNY 300K；总体目标上限 CNY 400K，未提供更精确的逐城市目标 | 税前年总包，同样保留各组成部分及条件。 |

同地区、薪酬口径和证据质量下，提高可比年薪不应降低评分，目标上限是达到 5 分的锚点，不是可接受收入的上限。本标准保留已确认的文字锚点，不引入 4–5 分之间的插值公式；小数结果在后续真实样本实验中检验，不要求现在猜测算法。

**独立充分性问题：**

> 现有同公司薪酬样本或公开薪酬制度，能否为薪资吸引力提供有边界的初筛参考？金额资料应保留币种、周期、地区、参考职级及已知 base / bonus / equity 口径；不要求确认本岗位定级或个人授予条款。制度信息也有参考价值；仅凭制度存在不能证明金额达到个人底线，其他地区金额不能冒充目标地区金额。

公开来源提供奖金、股权类型、保证／浮动性质或归属规则时保留；不要求查明个人绩效目标、授予额、首年折算、支付日、追回和离职处理条款。制度声明本身可以提供参考，不必等所有金额和条件齐备；没有可比金额时不推算薪资比值，也不能证明达到个人底线。香港仍按保证底薪比较，浮动奖金、未归属股权、福利或 MPF 不补足底薪缺口。

参考资料不要求证明适用于具体岗位。地区、职级、时间和薪酬口径的不确定性作为局限保留，不自动判为无效；已知不同地区的金额只作背景，不能混算目标地区薪资。核心金额无法辨认、来源不可追溯或实质矛盾无法解释时才不能支撑金额比较。薪资未披露不等于零薪资或低薪。

泛行业薪资中位数、城市／行业市场统计及其他雇主金额，不进入本岗位 `compensation` 输入、评分、充分性或岗位薪资参考说明。当前 `inputs/targeting.md` 和旧实验保留的行业基准不是本方案可用输入；个人底线与目标继续保留。不能用这些行业金额或公司声誉补齐缺失的雇主证据。

## 充分性与推荐的关系

充分性衡量现有资料能否提供有边界的初筛参考，不衡量内部信息齐备度或具体 offer 是否已核实。相关事实可用于决策；低充分性不使事实无效，不触发自动复核。数值不是资料覆盖率或评分正确概率，不设固定充分性门槛。

正式推荐按四维分数执行：四维均有数值且各自至少 4 分才为 focus；缺失或低于 4 为 deprioritize，明确硬性不符合为 discard。confidence 和充分性独立展示，不另设推荐门槛，不构建总分或跨维度排名。用户比较岗位时可以结合有明确范围的文化、薪酬等参考事实。
