# LinkedIn 有界 429 退避：实现与全配置验收

2026-10-18，北京时间 **10:18:16–10:27:01**。修改后按原配置运行一次只读采集：**525.048 秒（8 分 45.0 秒），141 个有效且不同 ID 的职位**。13 个遭遇 429 的职位全部在有限重试后恢复；两个来源最终由原采集预算结束，没有因 429 清空队列。

## 最终行为

仅 LinkedIn 搜索与详情请求新增 HTTP429 重试：每个请求最多 **2 次重试，共 3 次尝试**；默认等待 10 秒、20 秒。复用已有 `parseRetryAfterMs` 与 `sleep`，较长的 `Retry-After` 可增加等待，单次封顶 60 秒。

- 详情重试耗尽：记录失败，继续该关键词剩余候选和其他关键词。
- 搜索重试耗尽：记录该搜索失败，停止该关键词的后续搜索，其他关键词继续。
- 401/403/405 保留原来源停止行为；其他错误不新增重试。非 LinkedIn 的 web 搜索策略不变。
- 重试、共享导航间隔、导航和内容读取共用同一来源 deadline。等待不足以放入剩余预算时结束采集；计时器唤醒后重新检查。浏览器操作 timeout 按剩余预算缩短。
- 沿用每来源十分钟总预算中的 **525 秒采集窗口与 75 秒预留**；不通过重试延长窗口。一个来源到期不会让共享导航队列的后续调用持续失败。

## 实验设置

与[无重试基线](linkedin-original-full-discovery-2026-10-18.md)相同：当前 profile 的 `AI`、`AI Agent`、`Full Stack`、`Backend`，两地区 China / Hong Kong SAR，每地区最多 100 个有效职位、每关键词最多 10 页，两来源并发，保留共享 2 秒导航间隔。最近 7 天、全职、最新排序。

直接运行生产 `search.fetch`，只在 Playwright 边界记录每次导航、读取和 HTTP 状态；没有替换搜索或读取回调。使用原未登录隔离浏览器，没有接入用户 Chrome。只保存本地实验文件，**没有调用业务库写入、prescreen、评分、发布或申请流程**。模型调用为 0，模型 API 费用为 $0，不含外层 Codex 对话和本地计算费用。

## 未通过与覆盖边界

除已恢复的 429 外，两次已发出导航的详情没有返回有效 JD：

1. 中国大陆 Syntronic，全栈开发工程师 校招，`4477053032`：HTTP200，结构化 description 只有 **168 字符**，未达到原有 200 字符下限。没有放宽校验以增加成功数量。
2. 香港 EY，Advanced Analytics and AI Lead，`4469476876`：窗口末尾仅余约 254 毫秒，导航 timeout 已缩短至剩余预算并超时，没有继续重试。

另有中国大陆 HSBC，AVP CRM Full Stack，`4463349700`，已从队列选中，但因剩余预算不足以完成导航间隔，在发出导航前停止。这项不计入上表的 143 个已导航职位；若把该项也纳入已选中的详情任务，任务成功率为 **141/144 = 97.92%**。

8 个关键词/地区组合均读到第一页，未完成后续分页。两个来源均返回 `truncated=true / incomplete_details`，未达到每来源 100 个有效结果上限。141 个有效 JD 是来源采集记录，不是业务库新增职位数，不代表完整市场覆盖，也不证明每个职位当前仍接受申请。

本轮直接证明了 13 个 429 的重试恢复，以及预算内继续采集的行为；两轮网页内容和限流状态可能不同，不将单轮差异视为长期成功率或吞吐保证。
