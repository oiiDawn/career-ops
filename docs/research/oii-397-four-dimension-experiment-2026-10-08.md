## 受控边界探针：失败仍存在

首次 9 个探针明确写为人工假设，不是真实 JD 条件。其 Noul 0.08–0.12 表示没有实证来源，这本身不应称充分性错误。首次还让 Score 同时看到真实 JD 和假设标记，可能将来源可信度混入吸引力。为分离该歧义，仅追加 7 个有限澄清对照：简短闭合假设 JD；可信请求 instructions 要求 Score 假定指定事实成立，Noul 仍检查实际来源。原探针请求/响应不覆写，标准不改。澄清构造已完整冻结在 `probe-clarified/cases.json` 的 `request` 字段及每个 `.request.json`，这就是可复现输入；不为生产入口新增可配置指令接口。用现有入口的 `call` 原样回放这些冻结请求，输出到新目录即可：

```bash
.venv/bin/python -B - <<'PY'
import json, runpy
from pathlib import Path
from dotenv import dotenv_values
api = runpy.run_path("scripts/experiments/jev-score.py")
source = Path("data/experiments/jev-four-dimension-2026-10-08/probe-clarified")
output = source.parent / "probe-replay-new"
output.mkdir(exist_ok=False)
for case in json.loads((source / "cases.json").read_text()):
    api["call"](case["id"], case["request"], output, dotenv_values(".env")["TYPESAFE_API_KEY"])
PY
```

此命令会重调已授权的同一 API；不是本轮新增调用。

澄清后文化仍全部越过硬上限；r=.70 仍为1.29，目标上限仍为4.96。首次 r=.69 的1.38反而高于r=.70的1.34，出现非单调；澄清后1.19→1.29恢复这一对的单调性，却仍分错档。人工探针中350K底线的薪资在40/45/48净小时下首次为3.89/3.90/3.89，澄清工时组均3.99，未见明显工时调薪，但不是所有市场/班制的完整保证。

Jev Score 是分布期望，不是保证只落在某个分档/上限内的规则执行器；部分极端档只要残留其他档概率，原始映射+1就会越界。本轮没有悄悄取整、封顶或改 confidence，没有自动LLM复核/fallback。生产接入前需要明确哪些硬规则由确定性事实约束落实，并保留原始模型结果；这需要后续方案决定，未在本轮擅自实现。
