# 每日岗位评估报告模板

> 供“机会搜寻与评估”模块的 cron 输出使用。报告最终投递到 Discord，Discord **不渲染 Markdown 表格**，一律用紧凑列表，禁用 `|` 表格语法。只保留标题、统计、列表；不写方法说明、合规声明、总结或建议。

```markdown
# 每日岗位评估 — {YYYY-MM-DD}

**本日变化**：新增 {N} · 淘汰 {N} · 新评分 {N} · 过期 {N} · 待定 {N}

## 当前推荐池（全部 ≥4.0）

当前 `## Scored` 中所有仍有效且评分 ≥4.0 的岗位，按评分降序；不限本日新增。每行格式：评分｜公司/岗位｜城市｜薪资。

- 4.4｜NLS Executive Search / Senior AI Engineer｜香港｜待核验
- 4.4｜平安健康保险 / 智能体工程师岗｜深圳｜待核验
- 4.2｜Banclogix / Senior AI Developer｜香港/深圳｜60–90K

## 本日新增评分

### 推荐申请（≥4.0）
- 4.4｜公司/岗位｜城市｜薪资

### 可考虑（3.5–3.9）
- 3.6｜公司/岗位｜城市｜薪资

### 不建议（<3.5）
- 3.2｜公司/岗位｜城市｜薪资

## 本日硬门槛淘汰
- 公司/岗位｜理由类别

## 本日已过期
- 公司/岗位

## 待定（JD 缺失）
- 公司/岗位｜缺失项
```

## 固定规则

- 每项用一行 `- 字段1｜字段2｜字段3｜字段4`，字段之间用全角竖线 `｜` 分隔。
- 评分表统一四字段：**评分｜公司/岗位（`公司名 / 岗位名` 合并）｜城市｜薪资**。评分列在最前。
- 薪资从评估证据/报告中提取实际数值或区间；未知写 `待核验`，不写猜测值。
- 城市未知写 `待核验`；空分类保留表头并写 `- 无`。
- **绝不使用 `|` 竖线 Markdown 表格或任何表格语法**，全部用上述列表行。
- 结尾禁止添加任何处理说明、总结、建议或方法说明。
- 用户从 `## Scored` 选定岗位后，手动触发“申请准备与投递”；日报不进入 Stage 2。
