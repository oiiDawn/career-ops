# 每日岗位评估报告模板

> 供“机会搜寻与评估”模块的 cron 输出使用。报告最终投递到 Discord，Discord **不渲染 Markdown 表格**，一律用紧凑列表，禁用 `|` 表格语法。只保留标题、统计、列表；不写方法说明、合规声明、总结或建议。

```markdown
# 每日岗位评估 — {YYYY-MM-DD}

**本日变化**：新增 {N} · 淘汰 {N} · 新评分 {N} · 过期 {N} · 待定 {N}

## 当前机会池
运行 `node scoring-decisions.mjs`，严格使用返回的 decisions 顺序与 action 分组：推荐申请（apply）、优先补证（verify）、暂缓（deprioritize）、硬门槛不符（discard）。每项展示吸引力范围及覆盖率｜公司/岗位｜城市｜薪资；不能把区间变成单分或按下限重新排序。

### 推荐申请（apply）
- 吸引力 3.50–4.50/5（覆盖率75%）｜公司/岗位｜城市｜薪资

### 优先补证（verify）
- 吸引力 2.40–5.00/5（覆盖率35%）｜公司/岗位｜城市｜薪资

### 暂缓（deprioritize）
- 吸引力 2.00–2.99/5（覆盖率50%）｜公司/岗位｜城市｜薪资

### 硬门槛不符（discard）
- 吸引力 4.00–4.50/5（覆盖率60%）｜公司/岗位｜城市｜薪资

## 历史评分待重评
展示 `node scoring-decisions.mjs` 返回的 needs_review；不按旧分数推荐，也不隐藏这些机会。

## 报告校验失败
展示 invalid 及失败原因，不放入推荐申请组。

## 本日新增评分
按上述四种 action 分组；旧模型新写入的报告归待重评。

## 本日硬门槛淘汰
- 公司/岗位｜理由类别

## 本日已过期
- 公司/岗位

## 待定（JD 缺失）
- 公司/岗位｜缺失项
```

## 固定规则

- 每项用一行 `- 字段1｜字段2｜字段3｜字段4`，字段之间用全角竖线 `｜` 分隔。
- 评分表统一四字段：**吸引力范围及覆盖率（`吸引力 L–U/5（覆盖率P%）`）｜公司/岗位（`公司名 / 岗位名` 合并）｜城市｜薪资**。吸引力字段在最前。
- 评分只取 `node scoring-decisions.mjs` 返回的 `attractiveness` 区间与 `coverage`，由代码重算；**不得把区间折成单分，也不得按下限重新排序**。旧单分阈值（4.0/3.5/4.5）不再使用。
- 薪资从评估证据/报告中提取实际数值或区间；未知写 `待核验`，不写猜测值。
- 城市未知写 `待核验`；空分类保留表头并写 `- 无`。
- **绝不使用 `|` 竖线 Markdown 表格或任何表格语法**，全部用上述列表行。
- 结尾禁止添加任何处理说明、总结、建议或方法说明。
- 用户从 `## Scored` 选定岗位后，手动触发“申请准备与投递”；日报不进入 Stage 2。
