# 评分试点修复记录

已修复校验漏检并增加只读决策命令，正式评分流程尚未切换。

## 已修复

- 正文每个维度只能有一行，分数和权重必须匹配冻结配置；总分范围只能出现一处。重复冲突行、错误权重及重复范围进入回归测试。
- 机械一致性与语义验收分开。CLI必须读取报告旁的 `.review.json`，包含独立复核者、整份报告哈希和六项实质检查。改引文或正文会使既有复核过期；缺少复核、revise或检查未通过不能交付。姓名标题虽是真引文，也不能复用之前的语义批准。
- 哈希验证是完整性检查，复核记录是责任记录；两者都不是对真实性或正确性的数学证明。独立复核者仍可能判断错误，报告不得称“反幻觉根治”。
- 决策可接受线暂按已确认的3分可接受语义配置。硬门槛Fail优先discard；否则上限低于线deprioritize；否则门槛未知、申请条件未核实或区间跨线verify；其余apply。等于线算达到。缺完整JD的对象不产生评分报告，也不能进入该队列。
- 分类后按已知截止日期、预计工作量、覆盖率排列，仅apply组再比较下限，最终按id稳定打破平局。真实两岗日期与补证成本均无依据，使用null；不猜测机会时效。此排序是行动顺序，不是相互重叠范围的满意度排名。
- 队列只接受通过独立语义复核的报告，门槛和ready须与复核一致；不同评分权重/模型不能混排。程序没有写pipeline/tracker或发送申请的路径。

## 校准范围

增加 [8个明确虚构场景](cases.json)，含6个校准场景、2个未给参考答案的留出场景。两位评估者分别读取相同规则和材料，待遇/团队/公司共24项判定一致，覆盖1–5档和Unknown。原始记录：[A](calibration-a.json)、[B](calibration-b.json)。

这验证规则在明确场景中可执行，不是新增真实岗位校准。两位评估者也都提示“显著超过目标”和“远程选择”的相邻档边界仍有解释空间；分数一致不等于这些边界普遍无歧义。没有为追求一致而把合成场景伪装成招聘证据。

真实A2B2/NLS只有35%权重有证据，独立复核后仍只能进入verify：[行动结果](decisions.json)。原三维缺真实证据的问题仍是上线前限制；不能凭这些测试宣布生产可切换。下一步需要实际岗位的保证薪资、同团队工时/管理证据及业务资源信息，才能补真实留出样本；不以公司宣传、薪酬上限或模拟数字代替。
